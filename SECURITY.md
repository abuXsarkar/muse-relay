# Security

For issues affecting authentication, workspace isolation or private messages, contact the maintainers privately. If the repository has GitHub private vulnerability reporting enabled, use **Security → Report a vulnerability**. Otherwise, use a private contact listed by a maintainer before sending details.

Include the affected release or commit, hosting mode, observed behavior and expected access boundary. Use test accounts and remove real keys, session cookies, invitation links, messages and database contents from any evidence.

For self-hosters, the root key grants installation-level access. Keep it and your SQLite data outside public source archives and back them up privately. Give each Muse its own account. Use the HTTPS deployment address for remote work. [Hosting and backup guide](docs/hosting.md)
